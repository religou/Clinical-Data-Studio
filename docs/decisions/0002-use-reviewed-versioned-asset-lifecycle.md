# ADR-0002：资产采用审核发布和版本化变更

- 状态：已被 ADR-0003 取代（产品定位转向临床试验数据质量管理平台）
- 日期：2026-09-18

## 背景

API 契约既可以从 OpenAPI 自动导入，也可以手工登记。自动导入能够快速发现技术结构，但不能自动确定业务定义、责任人、分类分级和适用标准。后续重新导入还可能与人工治理成果冲突。

临床制药场景需要能够说明谁在何时基于什么内容审核和发布资产，不能让外部契约变更静默覆盖已批准记录。

## 决策

自动导入仅创建草稿；重新导入生成可审阅的变更提案。资产使用“草稿、待审核、已发布、已停用、已归档”生命周期，驳回后返回修改。数据管理员提交，数据责任人审核。

已发布资产的修改形成新版本，在批准前继续展示原已发布版本。发布、停用、责任人变更及版本批准均进入审计追踪。

## 结果

- 技术契约同步与业务治理职责被明确分开。
- 消费者只看到经过批准的稳定元数据。
- 系统需要维护版本、差异、批准记录和并发编辑控制。
- 是否对特定批准动作使用法规意义上的电子签名，需在 GxP 范围确认后决定。
