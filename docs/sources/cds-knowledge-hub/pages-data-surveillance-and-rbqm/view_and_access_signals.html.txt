# View And Access Signals

## View And Access Signals
## Access and View Signals
 You can view your study's current set of signals as well high-level details associated with each signal. 
- Access RBQM , and then click Signals in the left-hand menu.
The Signals table shows the following:
 Column Descriptions 
- Signal ID   – Signal number associated with the auto-generated or user defined signal. 
- Site – The site associated with the signal.
For QTLs, the site reads as "All Sites". 
- Country  – The country where the site is situated. For QTLs, the field reads as "All Study Countries".
- Patient  – One or many patients who meet the signal threshold at the site. The field shows up to 10 patients, with the remaining concatenated with a "+" icon. 
- Analysis – One module from Patient Profiles, KRIs, QTLs, Under and over Reporting, Rounding, Propagation, or Potential Duplicate Patients. 
- Name – The variable for the module on which the signal is generated. Some example are  KRI Name, AE Entry Delay, Missing Visit Percentage, Manual Query Rate,Non-System Query Delay, Percent Out of Window Visit, Number of SAEs per Patient-Month, Number of AEs per Patient-Month etc. 
- Observation – An automated observation based on the text used in signal threshold. Updated observation values appear in the signal report only if the value is at or above the set threshold. Sample description text for a KRI AE Entry Delay of 17 days when you set a threshold as "high" - The AE Entry Delay of 973 exceeds the threshold of 17 .
 Note : If the observation value falls below the module's configured threshold, it does not get updated when you refresh Signals data. The last value at which the threshold was met shows as the observation.
- Description – A description based on a combination of the observation and a system defined or custom description you entered while configuring the signal for a module. Sample Description text - The site is an outlier considering the time it takes to report AEs (considering AE Visit Date and First Entry Date). Please follow up with the site to ensure adequate processes and resources are in place. 
- Due Date – The due date for the signal. 
- Status – A signal has the following statuses: 
- Open – A signal assigned to an assignee. 
- New  – A newly created signal not yet assigned to an assignee. 
- Resolved – A signal marked as resolved. 
- Watched – A signal that may require intervention or action, but currently is being watched. No action is made upon a watched signal, it is not assigned to an assignee. 
- Dismissed – A signal that is dismissed. For example, if the observation may not be a potential issue for the time period in review. 
- Closed – A signal closed as no longer of interest. 
- Reopened – A signal reopened after it was closed. 
- Assignee – The name of the person assigned to the signal for further action. If no assignee exists, click the  Add assignee option to assign the signal to an assignee. 
- Category – Select from a list of existing categories or create a new category. 
- Opened By – The person who opened the signal. 
- Opened Date – The date the signal was opened. 
- Closed By – The person who marked the signal as closed. 
- Closed Date – Date the signal was closed. 
- Issues – A yes or no value that indicates if a signal is an issue. 
- Issue Type – A signal can have a protocol deviation or a non-protocol deviation issue type  
- Issue Target – An issue associated with a signal can be external or internal. 
- If necessary,  filter or sort the Signals table. 
## Filter the Signals table
- If necessary, access the Signals table . 
- Click the Filter button, at the top-right corner of the Signals table. 
- Click one or more of the following filters:
- Signal ID  – Filter to show specific signals. 
- Site – Filter to show signals based on sites.  
- Country – Filter to show signals in the country where the site is situated. 
- Patient – Filter to show one or many patients who meet the signal threshold at the site. 
- Analyses – Filter to show signals based on the modules configured for signal generation. 
- Name – Filter to show signals based on the module's variable on which the signal was generated. 
- Status – Filter to show signals by specific status. 
- Optional . Select one or more filter items. 
- Click Apply .  
- If necessary, click Clear Filters to revert to the Signal table's default view. 
## Sort the Signals table
- If necessary, access the Signals table . 
- In the Signals table, click any column header to sort the table by column in ascending alphanumeric order. 
- An up arrow, , appears next to the column name. 
- Click a column header twice to sort the table by column in descending alphanumeric order.
A down arrow, , appears next to the column name.
