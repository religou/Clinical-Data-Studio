# KRI Descriptions and Calculation Methodologies

## KRI Descriptions and Calculation Methodologies
 You can view and track system KRIs and custom KRIs in the KRI Dashboard . 
## System KRIs
 System KRIs are Medidata-defined KRIs that are standard in all studies analyzed by RBQM. Medidata defines the calculations that are performed on specific data sets and variables based on metrics that most studies typically track. Medidata always provides all customers with the system KRIs. System KRIs are uneditable and in an active state by default; however, you can deactivate system KRIs as needed. 
 The following table lists:
- The current system KRIs you can track in the KRI Dashboard . 
- The KRI category to which the KRI belongs . 
- A description for each KRI. 
- How RBQM calculates each KRI's values. 
 Important : For a KRI and its KRI value to be included in the KRI Dashboard, your study requires:
- At least three sites or three countries to match the minimum data requirements listed in the table below. 
- At least two enrolled patients at each site or country. 
 Important : If there are fewer data points at the site and country level, the statistical model that calculates KRIs may produce less accurate outcomes.

## Custom KRIs
 In addition to system KRIs , you can track user-defined custom KRIs in the KRI Dashboard . Custom KRIs help organizations target and track unique and specific endpoints or area of interests for risk analysis. Authorized users in your study environment can create and activate custom KRIs using Medidata's KRI Configuration . With KRI Configuration, you can create numeric KRIs or percentage KRIs . To learn more, see Add and Edit Custom Numeric and Percentage KRIs . 
 Note : Screen Failure (SF) Rate is no longer available as a system KRI, but you can set it up as custom KRI for studies where SF patient's data is collected in Medidata Rave. In Rave, the patient's Rave Patient Status must be tagged with Screen Failure. 
 Important : For a KRI and its KRI value to be included in the KRI Dashboard, your study requires:
- At least three sites or three countries to enable calculating custom KRIs. 
- At least two enrolled patients at each site or country. 
## Custom Numeric KRIs
 A custom numeric KRI is a key risk indicator that analyzes a single user-specified variable or data set and produces a numeric output for the results or observances. Numeric KRI value calculations are based on one of the following variable types: Mean, Count, Rate, Count Values, Rate Values, Standard Deviation. For example, you can calculate the mean of blood pressure values in your study to determine if any sites or countries show signs of risk regarding blood pressure data. 
 For numeric KRIs, you define: 
- A unique name for the custom KRI. 
- The data sets and variables you want to perform calculations on. 
- The type of calculations you want performed on the data sets and variables: 
- Count  –  Calculates the average record count in the selected data set. The Count calculation is only available at the data set level. This calculates count at the patient level for each site and country and then takes average of patient-level counts to arrive at site-, country-, and study-level values. 
- Count Values – Calculates the average count of records in the study that meet a specified criteria based on the selected field. Valid only for fields with a value of 1 or 0. This calculates count at patient-, site-, country-, and study-level values. 
- Mean  – Calculates the mean value of a numeric data field based on the selected variable at the site. This calculates the mean of a variable at the patient/site/country/study level depending on the values users are seeing. 
- Rate  – Calculates the total average record count divided by patient time on study in months in the selected data set over time. The Rate calculation is only available at the data set level. This calculates rate for a dataset at the patient/site/country/study level depending on the values users are seeing. 
- Rate Values – Calculates the average percentage in a site of non-missing, non-zero values for a given variable. Use cases include the fraction of Adverse Events which are Serious, where Serious was 1 for an SAE, and 0 for a non-SAE event, or the fraction of a lab parameter out of normal range. Valid only for fields with a value of a 1 or 0. This calculates count at patient-, site-, country-, and study-level values and multiply by 100.
- Standard Deviation – Calculates variance in a set of observed values based on the selected field. This calculates value for a field at the patient/site/country/study level depending on the values users are seeing. 
## Custom Percentage KRIs
 A custom percentage KRI is key risk indicator based on a user-defined binary expression that assesses whether or not patients meet specified conditions or criteria within a targeted risk area. Percentage KRI value calculations appear as percentages. For example, the percentage of patients who experienced serious adverse events. Or the percentage of patients with a history of hypertension who had thrombocytopenia between study days 5 and 10. 
 For percentage KRIs, you define: 
- A unique name for the custom KRI. 
- The specific risk category that you want the KRI to target its analysis on. 
- A functional expression for a numerator and denominator using date, number, or text variables within a study environment that queries your study database to assess if patients meet certain conditions or criteria. 
- The denominator includes the number of patients meeting the expression's criteria who are enrolled.
- If the denominator is not specified, it is taken as the total number of enrolled patients. 
- The numerator includes the number of patients meeting the expression's criteria who are enrolled and who also meet denominator criteria. 
 Note : Screen Failure (SF) Rate is no longer available as a system KRI, but you can set it up as custom KRI for studies where SF patient's data is collected in Rave. In Rave, the patient's Rave Patient Status must be tagged with Screen Failure. 
 When activated, a custom KRI's data is consumed, analyzed, calculated, and rendered in the KRI Dashboard .
