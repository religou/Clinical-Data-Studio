# Review Approved Listing Results

## Review Approved Listing Results
 You can use Data Surveillance to investigate and review an approved listing's results. As part of the review process, you can:
- View, sort, and filter an approved listing's results. 
- Add, view, edit, or delete internal review comments on individual records captured in listings. 
- View and submit Medidata Rave queries on patient records. 
- Mark individual records as reviewed or unreviewed. 
- View and export the audit trail of actions made on the listings' records 
## View an Approved Listing's Results
 You can view all data records captured by an approved listing's conditional expression. You can then perform any necessary investigative or review actions on those data records.
- 
 If necessary, access and view your study's approved listings 
- Access Data Surveillance , and then click Listings in the left-hand menu.
The Listings page shows. 
- On the Listings page, click the  Approved Listings tab.
The Approved Listings table shows the following:
 Column Descriptions 
- Name – The listing's object identifier (OID). 
- Expression – The listing's user-defined conditional expression, which Data Surveillance runs against your study data to capture the patient records within a specified variable that match the expression's defined specifications. In general, expressions are built to identify and report high-risk data points that your study team can review and investigate as necessary. 
- Rave Enabled – A check mark indicates that you can submit Rave queries on the patient records captured by the listing. 
- Refreshed By – The last user who refreshed the approved listing to show the latest results. 
- Track – Enables you to activate or inactivate the approved listing for Clean Patient Tracker analysis. To learn more, see  Track and Untrack Individual Approved Listings for Clean Patient Data Analysis . 
- If necessary, filter or sort the Approved Listings table.

## Filter an Approved Listing's Results Table

- Only data records for specific tables columns 
- Only unreviewed listing results. 
- Only reviewed listing results. 
- Only listing results for specific patient IDs, sites, countries, or variables. 
- Only listing results for specific variables whose data records contain specific values or values within a specific numeric range.

## Customize Column Configurations
 You can customize column configurations directly using the   More icon, above the Listing table when previewing a draft or approved listing. 
 Note: 
- If you specify column configuration while creating a draft listing, the listing retains the configuration when it is approved. 
- You can reconfigure columns of an approved listing, but these changes are temporary and only visible to you. If you refresh or reload the page, the columns revert back to the original configuration. 
- If you move an approved listing back to draft listing without modifying the expression, the column configuration remains unchanged. 
- If you edit the expression in an approved listing, newly added columns are automatically enabled for column configuration, and the existing columns retain their original configuration. 
- If you use the Copy Listings or Import Listing feature, you lose column configuration of the original listing. 
 Fix Column Configurations 
 To better customise the results, you can hide, unhide, fix a table's columns to appear to the left or right. For example, you can hide columns of no interest.
- If necessary, view an approved listing's results . 
- Click ,  More icon, above the Listing table. 
- Click Columns Configuration .
A slide out panel appears. 
- Drag and drop fields under Columns to either Left Fixed Columns or Right Fixed Columns . The fields you place under each appear as such in the listings table. For example, you fix Patient, Site or Country to the left.
 Note : We recommend:
- Fixing only Patient, Site and Country columns as left columns. 
- Only fixing columns that you can see on your screen as per your screen resolution. 
- Including some columns that are neither fixed as left or right fixed columns, so that horizontal scrolling remains. 
 Do not fix all columns in the listings table. That is, fix some columns to the left, and the remaining to the right. This may cause the screen to freeze (UI Gridlock), where the fixed elements from the left and right sides have essentially met in the middle, leaving no room for the scrollable data to actually render.

## View and Submit Queries on Patient Records
 You can view and submit queries on EDC-enabled listings directly in Data Surveillance for studies using Medidata Coder or an external coder, or even an external EDC like Veeva. EDC-enabled listings allow you to directly within Data Surveillance view and submit standardized, predefined queries simultaneously on multiple patient records captured in the listing's results. EDC-enabled listings: 
- Save time and effort required to investigate and query patient records by allowing you to simultaneously query multiple patients records. 
- Ensure uniform, consistent query text on the same variable across multiple records. 
 Within Data Surveillance, you can only submit queries on patient records captured by EDC-enabled listings. 
 Note: You can submit EDC queries only if you have the Submit Queries building block access. To submit queries in Data Surveillance, you must have the required permissions to submit queries in Rave. Data Surveillance does not verify your query permissions in Rave. You cannot create EDC-enabled listings using the queries data set. 
We recommend you do not submit queries for system fields as Rave does not support query submission for the following fields:
 System fields 
- PATIENT ID 
- SITE 
- SITE COUNTRY 
- STUDY 
- ENVIRONMENT 
- PLANNED EVENT 
- PLANNED EVENT NAME 
- PERFORMED EVENT DATE 
- PERFORMED EVENT NAME 
- ITEM GROUP REPEAT KEY 
 Important: 
- Data Surveillance does not support bulk query submission for Rave queries on nested forms. 
- If your study uses Rave, you can submit queries for EDC enabled listings. If your study uses an external EDC like Veeva, you can submit multiple queries into Veeva for non-system fields in your study data. The query you submit appears approximately five minutes after submission in Veeva. The status icon appears updated on the Listings page for queries submitted into Veeva in approximately three hours. 
 Non-system fields

## View and Create Vendor Queries for Patient Records
 You can create vendor queries for approved listing records directly in Data Surveillance. You can group multiple patient records into vendor query sets and assign them to approved vendors within vendor groups for action. For example, the vendor can supply the missing records, or provide further clarification. Vendor Queries:
- Enable you to report and track issues with external data. 
- Act as a bridge  to relay queries and issues between vendors and Data Surveillance users. 
- Manages discrepancies and inconsistencies with vendors. 
- Facilitate faster reconciliation of Rave and external vendor data. 
 You can also build easily downloadable and shareable vendor query sets for vendor consumption and action. Alternatively, you can submit vendor query sets directly to vendors, receive responses and track the progress of submitted vendor queries. Vendor queries s ave time and effort by integrating vendor communication into your data review process and ensure study data integrity. 
 Note : You can create Vendor Queries only if you have the Submit Vendor Issues and Manage Issue Sets building blocks associated with your role in the Cloud Administration study group.

## Mark Individual Records as Reviewed or Unreviewed or In Progress
 You can investigate and review all data records captured by an approved listing's conditional expression. You can then mark records as reviewed; for example, if the record:
- Is acceptable or not considered a finding. 
- Was queried and received a sufficient response. 
 You can also mark records as unreviewed. For example, if during post-analysis, your study team determines that a record previously marked as reviewed is an actual finding that should have been queried. In which case, you can mark that record as unreviewed to ensure your team does, indeed, track and review the finding. Or perhaps a record was marked as reviewed in error and should revert to unreviewed. 
 You can also mark records as in progress; for example if the record: 
- Was queried, and no response received. 
- Is not yet acceptable as insufficient response received. 
 Marking records as in progress indicates that the reconciliation cycle is in progress, and not complete, hence the record cannot be marked as reviewed, but is not either completely unreviewed.
 Note : For records captured by listings that are currently being tracked for Clean Patient Tracker analysis , Clean Patient Tracker marks reviewed records as clean. All unreviewed records get counted in Clean Patient Tracker as unclean records and outstanding tasks.
