# Prepare Clinical Data Files

## Prepare Clinical Data Files
 Prepare files containing clinical data and clinical operational data to enable Medidata CTMS functionality for non-Rave studies. You can use variable or fixed data structures depending on the data domain you plan to load. 
 Note : If data collection does not match the defined Schedule of Assessment (SOA) file contents:
- Update the SOA as a post-production change to reflect the new pairs of visits and data sets as a post-production change. 
- Ensure the data provider updates the data file and associates data to the pairs of planned visits and data sets. 
- Add a visit – such as UNSCHEDULED – as a post-production change, and provide the data provider instructions for when to associate data to UNSCHEDULED visit.

## Organize Subject Disposition Data
 Identify a method to organize Subject Disposition data for loading. You can use one of the following methods: 
- Load data with the source data sets exported from an EDC system. 
- Load data using Subject Disposition data sets. 
## Method 1 - Load Data With Source Data Sets from an EDC System
 You can load the Subject Disposition data from source data sets that you export from an EDC system. Clinical data exported from an EDC system do not map to CTMS functionality and are therefore optional. The Medidata Data Fabric only requires fields pertaining to the required concepts to enable CTMS functionality.
- Prepare the Subject Disposition data file from your EDC system, and do one of the following to the extract: 
- Load all the clinical data into the system.
 Note : This option has an increased loading time.
- Exclude the optional clinical data fields to prevent loading clinical data into the system.
 Note : The system produces warning messages for fields skipped during data processing.
- Remove the clinical data fields from source EDC data extracts.
 Note : In the following example, the user loaded every field extracted from the EDC system. When doing so in your case, ensure that you include the correct Data Set and Visit metadata in the Schedule of Assessments SDM file to reflect the study design.

## Prepare Adverse Events Data
 You can extract clinical data for adverse events through the source EDC system. Many EDC systems have the native ability to create extracts of clinical data for adverse events. However, many EDC systems do not have the native ability to create extracts of operational clinical data. In those cases, please contact your EDC vendor to get those extracts. Once you acquire both clinical data and operation data, please contact a programming resource to merge them into a single data set for loading.

- Method 3 – Load Subject Visit data by loading source data sets exported from EDC system and loading a file for SDV data. 
- Method 4 – Load Subject Visit data by loading source data sets exported from EDC system including SDV data.

## Method 3 - Load Subject Visit Data from Exported from an EDC System and Load an SDV File Separately
 You can prepare Subject Visit data from source data sets that you export from an EDC system. 
 Clinical data exported from EDC system do not map to CTMS functionality and are therefore optional. Only fields pertaining to the required concepts are necessary to enable CTMS functionality.  
- Prepare the Subject Visit data file by extracting source data from your EDC system and doing one of the following to the extract:
- Load all the clinical data into the system.
 Note : This option has an increased loading time. 
- Exclude the optional clinical data fields to prevent loading clinical data into the system.
 Note : The system produces warning messages for fields skipped during data processing.
- Remove the clinical data fields from the extracted data file.
 Note : Regardless of the option you choose, map the required concept tags in the fields SDM file for each data set. Include the correct Data Set and Visit metadata in the Schedule of Assessments SDM file to reflect the study design when loading source system EDC extracts.

 Important : Special Rules for Queries Data  
- When loading Queries data, the data file must follow a fixed data structure. Ensure the data file matches the listed field names and field order.
