# Transform Variable Mappings

## Transform Variable Mappings
 When performing source-to-target mapping, you can use the Transformation Instructions tool to convert mapped variables to fit your needs.
- From the Create Transformations screen, create the transformation using one of the following methods:
 Important :
- You can only use a single method per transformation. You cannot use no-code modules and custom code in a single transformation. 
- You must use the standardized Date_INT field as the source field in transformations, rather than the Date field. For details, see  Interpolated Variables Behavior in Data Surveillance and RBQM 
- Transform with Modules – Use the Add Function menu while in the Field Transformation and Calculated Fields tabs to configure each transformation . You can also use the Add Condition button to add IF-THEN conditional logic to your transformation.
 Note :
- Some operations assume that you mapped multiple source variables to the target variable. 
- You can nest calculated fields to create complex calculations. 
- The Is Missing and Is Not Missing conditions are incompatible with data in the Time format. As a workaround:
- Create a calculated field for the Time field to convert the Time field to a String field. 
- In Field Transformation, apply Is Missing or Is Not Missing to the calculated field. 
- Transform with Custom Code – Enter the input transformation logic in the Custom Code tab's Code field with postgres SQL.
 Important : The Custom Code transformation option is deprecated. If you already transformed a dataset using custom code, the transformation still functions as configured. However, once you remove the custom code configuration, you can no longer access this option. 
 Tip : Custom Code Usage Notes 
 Use the form’s name as the form’s alias and project type as the target’s alias; for example: AE.field1 || CUST.AEOUT.
