# Listings: Query Rave Data using Derived Datasets

## Listings: Query Rave Data using Derived Datasets
## What Is New?
 You can submit queries for records with derived datasets for Rave query enabled listings.
## What Is the Impact?
## Users/Roles
 Data managers or users with the Submit Query building block.
## Workflow Process
 No impact to the workflow process.
## Other Applications
 No impact to other applications.
## How Do I Benefit?
 Data managers can submit queries for listings built with derived datasets and get information about Rave data in the listing, enabling faster data reconciliation and maintaining study data integrity.
## Where Do I See the Change?
- On the Data Surveillance tab > Listings page > Approved Listings tab > for a Rave-enabled query listing, the following occurs in the Rave Query Details section of the expression builder :
- No derived variables, or variables from external datasets, or those from third-party, vendor datasets appear for selection. 
- Only Rave variables from derived datasets appear. The folder field updates to read Derived from Expression . 
- The marking group shows the selection made when the listing was first created. 
- The Submit Query button remains enabled only for Rave variables from derived datasets. 
- The datasets used in the column and listing configurations include OIDs in the dataset table. 
- If you edit a Rave-enabled query listing, form and field only show Rave variables from derived datasets.

## What Else Should I Know?
 You must have the Manage Data Reviewer building block added to your role in Cloud Administration to submit queries for listings. Submitted queries appear in Data Surveillance approximately three hours after they are saved in Rave.
