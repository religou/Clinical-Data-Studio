# RBQM: Set Observation Thresholds For Modules Using Signal Configurations

## RBQM: Set Observation Thresholds For Modules Using Signal Configurations
## What Is New?
 In the Centralized Monitoring process , a signal is an alert or indication of a potential problem, risk, or deviation in a clinical study. Signals get detected remotely by analyzing study data centrally, and allow proactively identifying potential risks in the study data. Signals help sponsors focus resources on sites or issues needing immediate attention, improving data integrity and patient safety.
In short,  
- A signal is a potential issue identified through data analysis. 
- An issue is a confirmed finding, the result of a signal validated through central monitor review, site discussion, or site visit.  
 RBQM includes a new Signals feature that you can use to build automated signals. However, to produce automated signals, you must first configure the modules you want the signal to report on. You can configure signals in RBQM > Configuration > Signals. 
## What Is the Impact?
## Users/Roles
 Central Monitors, Clinical Research Associates (CRAs), users with View Detect CSM Configuration and Manage Detect CSM Configuration building blocks added to their Cloud Administration profile.
## Workflow Process
 Signal configuration includes two aspects. First, the modules included in the signals report. Second, the specific thresholds within the modules at which signals get generated. 
 While configuring signals for individual modules, you can set up thresholds based on which automated signals get created. You must also choose the modules you want the signals to report on. For example, if you do not enable KRIs in the Signals Configuration, and add custom configurations, no signals get created for any KRI in your study when the signals data refreshes. Once you configure a signal, observations appear as signals based on custom configurations and the latest data snapshot for individual modules.
## Other Applications
 No impact on other applications. However, automated signals get generated based on values you set up as thresholds for the following:
- Patient Profiles 
- KRIs 
- QTLs 
- Duplicate Patients 
- Rounding 
- Propagation 
- Under/over Reporting 
## How Do I Benefit?
 With automated signals, Central Monitors can aggregate and track signals, create and assign actions for signals, and investigate signals of interest. You can monitor values that appear outside the set threshold and investigate observations, if necessary. Consolidating signals from various analyses into a single, centralized report: 
- Streamlines the identification, tracking, and management of data quality issues across study data. 
- Allows for continuous monitoring and ensures that potential risks get mitigated before they escalate as issues. 
- Enhances efficiency, reduces manual effort, and improves decision-making for users involved in central monitoring and central statistical monitoring. 
- Provides clear, actionable insights, ensuring that critical data quality issues are identified and addressed promptly.

## Patient Profiles
 If you click Patient Profiles from the Settings pane, and then click Add Custom Configuration , the Add patient profile configuration page appears.
- Design –You can select one from a list of published designs. 
- Flags –You can select one from a list of flags associated with the published design. Flag names are unique within an approved patient profile design. 
- Description – An editable, default description appears. 
 You can add up to 15 distinct, custom configurations for Patient Profiles. A flag used in a custom configuration is no longer available in the profile design for another configuration.
 KRIs
## KRIs
 If you click KRIs from the Settings pane, and then click Add Custom Configuration , the Add KRI configuration page appears.
- Name – You can select one from the active KRIs configured on the RBQM > KRIs page. You can create 15 distinct custom configurations. A KRI you select in a custom configuration is no longer available for selection in another configuration. It becomes available only if you delete the saved custom configuration. If a KRI used in a custom configuration is no longer active, a label appears in the configuration row.  
- Threshold –You can select High or Medium. 
- Description – An editable, default description appears.

## Duplicate Patients 
 If you click Duplicate patients from the Settings pane, and then click Add Custom Configuration , the Add duplicate patients configuration page appears.
 You can type in the Description field or use the default description text. Once you save, the automated signal reports include signals on duplicate patients in your study.

## Rounding
 If you click Rounding from the Settings pane, and then click Add Custom Configuration , the Add rounding configuration page appears.
- Variable – Select one or more variables from the data sets configured on the RBQM > Statistical Monitoring > Rounding & propagation > Propagation tab.

- Threshold – This is a percentage and must be over 0. 
- Description – An editable, default description appears.

## What Else Should I Know?
- Only users with View Detect CSM Configuration building blocks added to their Cloud Administration profiles can view and download custom configurations. Users with Manage CSM Detect Configuration can add, edit, or delete custom configurations. 
- You can refresh data only once for the automated signals report.  
- You cannot generate or configure signals for Rounding and Propagation, if pivot is turned on under RBQM > Configuration > Data Mapping > Rounding and Propagation. 
- Custom configuration changes made after 6:00 AM EST do not show in the automated signals report until the next day.  
- For Statistical Monitoring modules such as Rounding, Propagation, Duplicate Patients, and Under/over Reporting, if the Signals workflow encounters an error with any one module, the automated signals report for that module shows observations misaligned with those shown on the module's dashboard. On the signals report, the Module Snapshot still reflects the latest snapshot data from that module. For example, if Rounding has an error, then the signals for Rounding may not align with the data shown on the RBQM > Statistical Monitoring > Rounding and Propagation > Rounding tab.
